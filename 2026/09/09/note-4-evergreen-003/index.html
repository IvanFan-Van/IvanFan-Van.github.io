本文尝试解决以下问题:

如何构建一个无限大小, 可拖拽缩放的幕布 web app.

无限幕布类应用有非常广阔的场景, 例如 tldraw 手写幕布, 可以用于记录笔记, 绘制架构图等.

又或是用于展示路径图, 例如 labuladong 的算法学习路径 算法刷题路线图

抑或是构建零代码或低代码开发平台, 例如 Dify - The Platform for Production-Ready Agentic Workflows

它们的核心底座都是一个支持自由拖拽、节点创建与连线的无限画布。

自由幕布虽然应用场景各异，但其底层的物理模型与核心计算公式极其相似。只要掌握了其精髓，就能轻松复用并在此基础上定制属于自己的应用层。

本文将带你深刻理解无限幕布的核心物理模型，一步步编写出完整、健壮的基础框架代码，并提供性能优化与架构进阶的指引。

任何 web 应用底层都是由 html, css, javascript 构建的, 所以在构建任何 web app 时, 只需要思考以下三个问题:

  1. 你的 app 应用应该包含哪些元素(component)
  2. 每个元素应当具备哪些特性 (形状, 大小, 位置, 锚点等)
  3. 每个元素应当如何响应用户交互行为 (例如鼠标, 滚轮)

而无限画布的本质其实很简单：用一个可以整体平移缩放的”世界容器”包裹所有内容，用户看到的画面 = 世界容器经过 translate + scale 变换后的样子。因此只要维护好 offset(x, y) 和 scale 这三个状态,剩下的都是围绕它们做数学计算。

在交互行为中, 幕布主要关注 pointer 和 wheel 事件

  • pointerup, pointermove, pointerdown 用于拖拽幕布, 移动物体, 框选等功能
  • wheel 用于缩放幕布操作.

那怎么移动幕布或是缩放幕布大小呢? 我们通过对 world 元素施加 transform css 属性来应用平移和缩放, 其中所有 world 的子元素都会被应用相同的平移和缩放.

如果只是简单地改 scale，画面会绕左上角缩放，体验很差。正确做法是：缩放前后，鼠标指向的那个世界坐标点，屏幕位置不能变。

浏览器有一个几乎所有主流引擎（Chrome/Firefox/Safari）都遵守的约定, 可以帮助我们分辨用户究竟希望使用触控板平移还是缩放幕布.

触控板双指开合（捏合手势） → 浏览器会派发一个 wheel 事件，并且自动把 ctrlKey 设为 true（即使你根本没按 Ctrl 键）
触控板双指平移 → 派发正常的 wheel 事件，ctrlKey 为 false，但 deltaX/deltaY 都有值（因为是双向平移）

通过判断 ctrlKey 是否触发, 我们就可以判断用户的意图, 来分辨触控板是要平移还是缩放幕布了.
