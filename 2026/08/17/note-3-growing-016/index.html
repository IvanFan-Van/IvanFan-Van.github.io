BBPE (Byte-level BPE) Tokenizer 复杂度是 O(N^2)

naive BPE Implementation

核心逻辑集中在 get_stats() 和 merge() 函数中

时间是 O(N). 假设 len(ids) 长度为 N. 需要遍历所有 pair 并统计频率.

时间是 O(N), 因为要遍历整个 ids. 重构整个 ids 数组.

假设 num_merges 为 M, 每一次循环内需要 get_stats(): O(N), merge(): O(N), max(stats, ...): O(N)

所以总的时间复杂度为 O(M * N)

如何优化?

  1. get_stats(): 是否需要每一次 merge 之后都重新统计? 由于 merge 操作只会更改一个 pair, 其他的 pair 的 freq 应该是相同的, 所以最优的情况我们应该只需要更新被 merge 影响的那些 pair 的频率.
  2. merge(): 每一次 merge 我们需要重构整个 ids, 由于是整个数组重构, 所以复制时间复杂度是 O(
    N), 但实际上我们只需要替换某个 pair 为一个 idx 即可. 可以使用双向列表来优化, 修改指针的复杂度是 O(1)
  3. max(stats, ...): 考虑更换最大堆来优化线性查找时间. 最大堆的插入时间复杂度是 O(logN)

因此优化后预期整个 bpe 时间复杂度降为 O(MlogN)
