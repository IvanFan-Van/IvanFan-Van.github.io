React Router 是一个能让单页应用切换页面的技术.

在早期没有 SPA (Single Page Application) 的时候, 每一个页面都是一个单独的, 完整的 html 文件. 人们通过 a 链接 访问不同的页面. 例如对于 home page 是 /index.html 文件, 对于 about page 是 /about.html.

但这种方式有一些问题, 首先就是对于大量页面, 可能仅仅只是数据的不同, 例如表格. 早期通过 javascript 中的 ajax 技术来异步获取数据并使用 js 编写 DOM 代码来动态修改 html. 这曾经流行了很长一段时间, JQuery 这个库也是在那个时候风靡全球, 基本上那个时候的所有 Web 应用都使用这个库.

而框架的诞生, 则帮助简化了这种 获取数据 -> 动态修改 html 渲染 的步骤, 同时利用虚拟 DOM 来极大的提高性能.

框架例如 Vue, React 通过定义一个 html 框架, 但是其中的数据都是一些变量填充的, 当变量改变时, 会同步修改页面上渲染的内容. 通过这种方式我们可以非常简洁的代替很多 js 代码, 避免直接操纵 DOM 元素. 实现了所谓的 命令式编程范式 到 声明式编程范式 的转变.

同时框架还提供了重复利用同一段 html 代码的功能, 这个代码片段被称之为组件.

通过 声明式编程范式, 组件化 以及 虚拟 DOM. 框架逐渐取代了曾经的老大哥 JQuery, 大家也渐渐不在手动操控 DOM 元素, 而是利用框架提供的响应式编程 API 来控制数据获取以及数据渲染的步骤.

那么为什么需要 react dom 库呢? 首先我们有一个需求就是, 当用户进入不同的 URL 地址时, 如果我们仅仅更新视图内容而不更新 URL 地址, 当浏览器刷新时, 会把所有的改变重新变回最初始的状态, 而不是刷新前的状态. 同时我们也无法通过转发 URL 的形式将我们看到的内容发送给其他人, 例如在一个电商 app 中, 我正在观看某个商品A, 点击按钮后触发 js 修改页面视图, 渲染一些图片啊以及对应的商品数据, 但是并不修改 URL , 我们的 URL 还是 www.example.com, 分享给其他人则其他人是无法看到我们看到的页面的.

第二个问题在于, 改变 hash 不会改变 URL, 所以浏览器历史记录中只会有一条记录, 当用户点击后退按钮时会回到上一个应用, 而不是你的应用的上一个页面. 除非我们手动往浏览器历史记录中添加, 通过 History API 中提供的 pushState 以及 replaceState 函数.

尽管通过维护一个全局的 currentRoute 以及 currentView 变量, 我们可以做到 URL 同步, 历史记录更新, 以及链接分享的问题, 但是这样非常繁琐且不容易维护.

所以 react router 出现了. 其核心目的就是解决以上这些问题, 将不同的组件映射到不同的 URL 上.

其通过提供一个声明式的 Route 组件来定义 URL 和组件之间的关系.

并且提供了 useNavigate 钩子来实现 a 链接的跳转效果, 帮助我们使用任意元素都可以进行跳转. 而 Link 以及 NavLink 组件则直接代替了 a 链接. 对于链接我们使用 Link 即可. NavLink 相比起 Link 提供了一个动态的 “active” 类, 当当前 url 和 NavLink 中的 to 属性相同时, 就会自动添加一个类 active, 这方便我们进行样式修改. 但对于通过按钮, 例如 login 等跳转我们可以使用 Button 结合 useNavigate 的方式. 或是表单提交后跳转等, 没有用户交互但是需要跳转的时候, 采用 useNavigate 可以掌握更多主动性.

并且提供了 useParams 钩子来帮助我们解析动态路由中的参数, 例如 /product/:id
